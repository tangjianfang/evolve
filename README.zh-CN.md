# evolve

**Claude Code 自我迭代进化协议 —— 把任意项目当成持续自我完善的系统。**

简体中文 | [English](README.md)

evolve 在任何项目上执行 N 轮小而完整的闭环迭代：

> **发现问题 → 解决 → 验证 → 提交 → 记录**

它从一次真实项目上**连续 181 轮迭代**的实践中提炼，泛化为适用于任意代码库的通用协议。

## 工作原理

每轮是严格的七步闭环，由一支资深工程团队驱动 —— 角色是资深的，执行是分层的（唯一的可写会话 + 在"独立性或成本划算"处外派只读子代理）：

| 角色 | 执行者 | 职责（对应机制） |
|---|---|---|
| 技术负责人 | 主会话 | 选目标、目标池优先级与刷新、收敛判定、史诗升级判定、diff 范围控制 |
| 资深 UX 质量工程师 | haiku 子代理 · 只读 · 只回问题清单 | 视觉走查（仅 UI 目标且有截图机制）：布局、溢出、对比度、缩放 |
| 资深代码评审员 | 主会话 | 代码 review：项目惯例 + 通用缺陷清单 |
| 资深开发工程师（唯一写者） | 主会话（绝不外派） | 修 bug、优化、小扩展 |
| 资深测试工程师 | 主会话 | 先红后绿、基线只增不减、执行锁定的 verify 命令 |
| 首席审计员（对抗验收） | 独立子代理 · 只见缺陷与测试、不见修复 | 反驳每一个修复声明 |
| 发布经理 | 主会话 | 每轮一个可回滚 commit、绝不自动 push |
| 知识管理负责人 | 主会话 | 轮次记录、lessons 库维护、教训结晶 |
| SRE 值班工程师 | 脚本（`auto-evolve.sh` + `breaker.sh`）无人值守 | 熔断、指标、checkpoint、回放审计 |

「资深」指的是职责与问责，不是模型档位：分权只设在两处最值钱的位置 —— 廉价的眼睛（UX 走查）与独立的眼睛（审计员）；所有持写权限的职责都留在单一可写会话（单一写者，E9）。

1. **选目标**：从四层优先级目标池取下一个（已知缺陷 → 测试缺口 → 模块轮转 → Backlog）；目标池每 10 轮重扫一次，不会拿过时地图迭代
2. **视觉 review**：委派 haiku 子代理执行；发现必须复核再动手（实践中约 15% 是幻报）
3. **代码 review**：项目惯例 + 通用项（错误处理、并发/锁边界、资源泄漏、死代码、硬编码、性能）；review 范围按模块大小成本分级
4. **行动**：每轮 1–3 项，按优先级：修 bug → 优化 → 小扩展
5. **验证**：按项目声明的构建/测试命令执行，全绿才算完成
6. **提交**：每轮独立 commit（`evolve #<轮次>: <一句话>`）；绝不自动 push
7. **记录**：向 `docs/evolve-log.md` 追加结构化一行（发现数 / 行动数 / 结果 / diff 行数），拨动指针，更新指标计数

循环会**收敛**：某目标连续 2 轮干净即移出池子；连续 3 轮全池干净且**零发现、零回归**触发提前终止 —— 靠数据说话，不凭印象。最后一轮固定是**复盘轮**，把教训沉淀进 `docs/lessons.md` —— 若流程本身有坑，还会反哺修订本 skill。

**史诗任务升级：**轮次刻意保持小（修 bug → 优化 → 小扩展）。当日志显示轮次级工作收不掉某个目标 —— 修复反复失败（≥2 轮红）、目标反复回锅、3 轮做不完、改动切不出能独立变绿的 ~300 行切片、或能力超出当前架构 —— evolve 不再硬磨，而是向 `docs/epics.md` 写一份提案（类型 重构/创新、触发证据、假设、实施方案草图）。**轮次绝不执行史诗任务**：提案在运行结束时浮出给你 review，只有批准的史诗才走自己的 spec→plan 流程。

长跑是一等公民：每 10 轮向日志写入 checkpoint 并交接给新会话、从指针续跑 —— 上下文压力不会拖垮轮次质量。

### 架构图

```text
输入: "迭代 N 次" / "/evolve N"   (未指定 → N = 5)
  │
  ├── 交互模式 ── 主会话逐轮执行 (唯一可写会话)
  │
  └── 全自动模式 ── scripts/auto-evolve.sh 驱动器
        每轮 spawn 一个 headless 会话, 提示词带 "round i of N"
        (不说位置 → 末轮复盘必漏, 实测踩过)
        熔断 scripts/breaker.sh: 连续 3 轮无进步 或 连续 3 个会话失败 → 停;
        头部 status: converged / pending-epics 亦是停机通道
  │
  ▼
Step 0 · 每会话必读: CLAUDE.md/AGENTS.md → docs/lessons.md → docs/evolve-log.md
  │      (evolve-log 缺失 ⇒ 首次画像: 探测构建/测试命令,
  │       定 verify 命令与基线, 建目标池)
  ▼
───────── 每轮七步闭环 · i = 1..N · 严格顺序 ─────────

  1. 选目标        从目标池按 Tier 1→4 取下一项 (指针存 log 头部)
      ↓
  2. 视觉 review   haiku 子代理, 仅 UI 目标且有截图机制
      │            (发现必须复核 — 实践约 15% 是幻报)
      ↓
  3. 代码 review   资深代码评审员(主会话): 项目惯例 + 错误处理/并发/泄漏/
      │            死代码/硬编码/性能; 模块 ≤ ~2000 行全读, 大模块按需扩展
      ↓
  4. 行动          本轮 1–3 项, 优先级: 修 bug → 优化 → 小扩展
      ↓
  5. 验证          执行 log 头部锁定的 verify 命令
      │            全绿才算数; 不绿 → result(red) / 权限卡死 → blocked;
      │            同一行动连续 3 红 → 记 red 收轮, 不恋战
      ↓
  6. 提交          "evolve #i: …" 独立 commit; 绝不自动 push (除非显式授权)
      ↓
  7. 记录          log 追加一行: #i | target | findings | actions | result | diff
      │            拨指针、更新计数 (头部计数必须 ≡ 轮次行之和)
      │
      ├─→ i < N: 回到 1  (每 10 轮: 写 checkpoint + 池刷新,
      │                 建议开新会话从指针续跑)
      │
      └─→ 目标触发史诗升级标准 (a–f)?
      │                  ──► 提案写入 docs/epics.md (占本轮行动位; 仅提案 ≠ 进步,
                              熔断 3 连续无进步即停); 运行结束浮出 → 用户 review
                              → 批准后走独立 spec→plan, 不由轮次执行;
                              分解出的切片可回到 Tier 4 backlog
──────────────────────────────────────────────────────────
  │
  ▼
终止: N 轮跑完 / 提前收敛 / 熔断 / 史诗待决 / 用户叫停  →  最后一轮固定 = 复盘轮
  回放审计 (git 快照重放, 剔除 gamed 轮)
  → lessons 更新 (verified+1 / 改写 / 删 — 教训库不许烂)
  → epics 登记复查 (改写/删除过时提案)
  → 流程改进 (踩的坑若已被教训覆盖 → 反哺修订 SKILL.md 源仓库)
  → 结晶 (≥3 条同主题教训 + ≥5 次验证 → 固化为命名机制)
  → 总结报告 (≥20 轮出 docs/evolve-report.md; 小运行在 log 里追加总结块)

═══ 横切层 ═══

【目标池 — 第 1 步的取件处】
  Tier 1 已知缺陷 (issue 文档逐条 grep 核实 — 文档会滞后于代码)
  Tier 2 测试覆盖缺口
  Tier 3 模块轮转 (按当前 src/ 结构重列)
  Tier 4 小扩展 backlog (大票务走独立 spec→plan, 不进轮次)
  刷新: 每 10 轮或绕池一周 — 剔已修、重列模块, 并入当轮
  收敛: 目标连续 2 轮干净 → 出池 10 轮;
        全池连续 3 轮零发现零回归且 backlog 空 → 提前终止

【反作弊护栏 — 每轮自检; 进步只认证据, 不认叙述】
  进步白名单四选一: 新增测试全绿 / 先红后绿 / 可测量改善 / 验收员确认的修复
  对抗验收员: 只给缺陷描述+测试, 不给修复, 指令是"反驳"
  新颖性守卫 (vs 最近 10 轮) · 难度守卫 (连续 2 轮琐碎 → 下轮强制 Tier 1)
  · 验证命令锁定 (改它需单独 commit) · 复盘回放审计

【状态外置 — 断点续跑的根基】
  docs/evolve-log.md   verify 命令 · 指针 · rounds done · metrics · 轮次行
  docs/lessons.md      教训库 (复盘轮维护: 计数/改写/删除/结晶)
```

设计要点一览:

- **小轮次、长运行** —— 每轮 ~300 行的 diff 上限让每一轮独立可回滚、可归因(一次回归就是一个 `git revert`;一个进步声明就是一个可回放的 commit)。大功能不会被挡住,而是走独立 spec→plan 分解成多轮落地。
- **状态存在你的仓库里** —— 指针、目标池、指标、教训:任何会话都可以死,下一个会话从指针续跑。
- **进步 = 证据** —— 白名单(新增测试 / 先红后绿 / 可测量改善 / 验收员确认)让"改进"可审计,而不是一番叙述。
- **流程自我改进** —— 复盘轮把教训沉淀进 `docs/lessons.md`,反复被验证的教训会被结晶成协议本身的机制。

## 项目数据文件

evolve 的状态保存在你的项目里：

- `docs/evolve-log.md` —— 验证命令、轮次指针、每轮一行结构化记录（发现 / 行动 / 结果 / diff）、指标计数器。示例行：
  ```
  #7 | src/ui/Toolbar | findings(2) | actions(2) | result(green, 148 tests) | diff(210) | 修复焦点丢失 + 失效快捷键
  ```
- `docs/lessons.md` —— 累积教训库，每条带可执行的"如何应用"

首次在新项目上运行？evolve 会自动做项目画像：探测构建/测试命令（CMake、package.json、pytest、cargo、go、maven、gradle，都没有就问你）、把已知 issue 文档逐条 grep 代码核对、建立目标池。起始模板随 skill 自带（`docs/templates/`：evolve-log、lessons、evolve-report、epics —— 最后一个在首次提案时才创建）。

## 安全红线（每轮自检）

- 遵循项目 `CLAUDE.md` / `AGENTS.md` 声明的边界与"不要做"清单
- 不自动 push；不动 vendored 依赖；不引入新第三方依赖
- 测试必须全绿（基线只增不减）
- 每轮 diff 控制在 ~300 行内，保持可回滚
- 修复 issue 条目必须在同一 commit 同步更新对应文档
- 破坏性命令一律要求确认

## 安装

**作为 Claude Code plugin（推荐）：**

```
/plugin marketplace add tangjianfang/evolve
/plugin install evolve@evolve-marketplace
```

**手动安装：** 把 [`skills/evolve/SKILL.md`](skills/evolve/SKILL.md) 复制到 `~/.claude/skills/evolve/SKILL.md`（用户级）或项目的 `.claude/skills/evolve/SKILL.md`（项目级），并把 [`docs/templates/`](docs/templates) 与 [`scripts/`](scripts) 一并复制到安装目录下的 `docs/templates/` 和 `scripts/` —— 首次运行做项目画像时这些起始模板会派上用场，`scripts/check-update.sh` 则支撑 Step 0 的协议漂移提示。

> **名称冲突提示：** 若同时安装了 `everything-claude-code` 插件，裸名 `/evolve` 可能被它的同名 skill 抢占。建议用自然语言触发（“迭代 20 次”——描述匹配会选中本 skill），或禁用冲突插件。

## 使用

自然语言即可触发：

```
迭代 50 次
evolve 30 次
/evolve 20
```

未指定轮数时默认 5 轮。随时可停 —— 状态存在 `docs/evolve-log.md`，下次运行从指针处继续。

**全自动模式：**零交互跑 N 轮——每轮一个 headless 会话，带熔断与反欺骗防线：

```
scripts/auto-evolve.sh /path/to/project 50
```

加上 `--dry-run` 前缀可只校验配置并打印执行计划（项目、轮数、权限、log 指针、熔断状态、钩子），不会启动任何会话——长跑之前先免费验证一遍接线。

前提：先手动跑一轮交互迭代（完成项目画像），并为项目配置 `.claude/settings.local.json` 权限白名单（或在可信项目上用 `--danger`）。成本随 N 线性增长——大 N 长跑前先用小 N（如 5 轮）试跑，确认画像与权限都通，再放量。白名单规则前缀必须匹配会话的 shell 工具——`Bash(...)` 规则不覆盖 PowerShell 会话（Windows 默认），需为 verify 命令和 git 平行添加 `PowerShell(...)` 规则，且 verify 需以单条命令调用（链式 `a && b` 无法通过静态校验）。每轮必须通过进步白名单挣得 `green+progress`——新增测试、先红后绿修复、可测量改善、或验收员确认的修复；连续 3 轮无进步或连续 3 次会话失败自动熔断；`status: pending-epics`（全部剩余目标停摆等待史诗决策）同样停机。仅当项目 log 头部声明 `push: auto-authorized` 时才自动 push。设置 `AUTO_EVOLVE_ROUND_HOOK='<命令>'` 可在每个成功轮次后执行一条命令（通知、部署、导出指标）——钩子失败只报告、绝不中断 run，失败的会话不触发钩子。
